# База AMBAR: где лежит и как поднять

Одна страница на случай, когда что-то сломалось, а спросить некого.

## Где данные

| копия | где | как часто |
|---|---|---|
| боевая | MongoDB на сервере `150.241.70.116`, порт 27017, только localhost | живая |
| файлы | `/opt/ambar/backups/ambar-ГГГГММДД-ЧЧММ.jsonl.gz` | каждый час |
| удалённая | MongoDB Atlas (кластер `ambar.wwz6b3o`) | каждый час, зеркалом |
| у владельца | Мак, `~/Desktop/.../TG/AMBAR/db-backups/` | автоматически, раз в 6 часов |
| вне периметра | Backblaze B2, бакет `ambar-db-backups`, папка `db/` | раз в 6 часов |

Формат файлов — Extended JSON построчно в gzip: читается глазами, не зависит
от версии драйвера, восстанавливается тем же скриптом.

Хранение: последние двое суток целиком, дальше по копии в день за две недели
и по воскресеньям за восемь недель.

## Копии в Backblaze B2

Шифруются до отправки (AES-256), лежат с включённой блокировкой: **удалить или
переписать файл нельзя тридцать дней никакими ключами, включая наши**. Через 45
дней уходят по правилу жизни файлов. Ключ приложения ограничен одним бакетом.

Пароль расшифровки — `/opt/ambar/.b2-pass`, второй экземпляр у владельца в
`db-backups/RESTORE-KEY.txt`. Потеряв оба, копии из B2 не открыть.

```
venv/bin/python tools/b2_upload.py --list     # что лежит в хранилище
venv/bin/python tools/b2_upload.py            # отправить свежую копию
openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 -in ФАЙЛ.enc -out ФАЙЛ.gz -pass file:/opt/ambar/.b2-pass
```

## Кто за что отвечает

- `ambar-backup.timer` — копия + зеркало, каждый час
- `ambar-watchdog.timer` — проверка сервисов, базы, копий, диска; пишет владельцу в телеграм при поломке
- `ambar-drill.timer` — учебное восстановление первого числа месяца, отчёт в телеграм
- `ambar-b2.timer` — шифрованная копия наружу, четыре раза в сутки
- `mongod` — сама база

## Если база не отвечает

```
systemctl status mongod
journalctl -u mongod -n 50
systemctl restart mongod
```

Не поднимается — переключиться на Atlas, это две команды и минута:

```
python3 /opt/ambar/tools/switch_db.py --to atlas
systemctl restart ambar-api ambar-bot ambar-operator ambar-owner-bot ambar-driver-bot ambar-support ambar-promo-bot
```

Обратно — `--to local`. Скрипт сам разбирается, где какая строка подключения,
и оставляет по одной строке на ключ в `.env`.

## Если сервер потерян целиком

1. Новый сервер, Ubuntu 24.04, поставить MongoDB 8:
   `curl -fsSL https://www.mongodb.org/static/pgp/server-8.0.asc | gpg -o /usr/share/keyrings/mongodb-server-8.0.gpg --dearmor`
   плюс репозиторий `mongodb-org/8.0` и `apt install mongodb-org`.
2. Забрать `/opt/ambar` из гита, положить `.env` (копия у владельца).
3. Взять самый свежий файл копии — с Мака владельца или из Atlas.
4. Восстановить:
   `venv/bin/python tools/backup.py --restore backups/ФАЙЛ.jsonl.gz --into ambar --yes`
5. Поднять сервисы из `deploy/*.service`.

Проверка, что всё встало: `venv/bin/python tools/watchdog.py --report`.

## Проверить копию, ничего не ломая

```
venv/bin/python tools/restore_drill.py --quiet
```

Разворачивает свежую копию в отдельную базу `ambar_drill`, сверяет количество
документов с боевой и удаляет учебную. Боевую не трогает.

## После перезагрузки сервера

Сервисы ждут `mongod` — это задано в `/etc/systemd/system/<сервис>.service.d/after-mongo.conf`
(шаблон лежит в `deploy/after-mongo.conf`). Если разворачиваешь всё заново,
положи этот файл каждому сервису и сделай `systemctl daemon-reload`, иначе
после ребута они поднимутся раньше базы.

## Что нельзя делать

- Восстанавливать поверх боевой без `--yes` — скрипт специально не даст.
- Держать две строки `MONGO_URI` в `.env`: библиотека читает последнюю, глаз —
  первую. На этом уже один раз потеряли час.
- Считать, что репликация заменяет копии. Удалённая коллекция удаляется на всех
  узлах мгновенно; спасают только файлы.
